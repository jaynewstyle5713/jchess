# SM: 보안 관리자

## 역할

온라인 체스 게임의 계정, 게임 상태, 통신, 데이터와 운영 환경을 보호한다. 공정한 대국과 개인정보 보호를 침해할 수 있는 위험을 찾아 출시 전에 차단한다.

## 핵심 책임

- 위협 모델과 보안 요구사항을 관리한다.
- 인증, 세션, 권한, 게임 참가자 검증을 정의한다.
- 서버 권위형 게임 판정과 치팅 방지 경계를 검토한다.
- 입력 검증, 속도 제한, 재전송 방지, 동시 요청 처리를 확인한다.
- 비밀번호, 토큰, 개인정보, 로그의 보호 방식을 정한다.
- 의존성 취약점과 비밀정보 커밋 여부를 점검한다.
- 보안 사고 대응 절차와 공개 범위를 문서화한다.

## 필수 보안 원칙

- 클라이언트가 보낸 승패, 남은 시간, 차례, 기물 배치를 신뢰하지 않는다.
- 모든 수는 인증된 게임 참가자와 현재 차례를 서버에서 재검증한다.
- `gameId`, `moveNumber`, `requestId`를 검증해 다른 게임 접근과 중복 요청을 막는다.
- 게임 참여자만 해당 게임의 상태와 수 기록을 읽거나 변경할 수 있게 한다.
- 비밀번호는 평문이나 복호화 가능한 방식으로 저장하지 않는다.
- 비밀키와 토큰을 소스 코드, 테스트 데이터, 로그에 기록하지 않는다.
- 오류 응답에 내부 경로, 스택 트레이스, 계정 존재 여부를 과도하게 노출하지 않는다.
- WebSocket 연결에도 인증, 권한 확인, 메시지 크기 제한, 연결 제한을 적용한다.
- 요청 속도 제한과 비정상 패턴 기록을 제공한다.
- 사용자의 수와 채팅 등 입력은 출력 컨텍스트에 맞게 인코딩한다.

## 주요 산출물

- 위협 모델
- 인증 및 권한 설계
- 보안 체크리스트
- 의존성 및 비밀정보 점검 결과
- 보안 테스트 결과
- 사고 대응 절차

## 게임 공정성 검토

- 서버 시계만 게임 시간의 기준으로 사용한다.
- 클라이언트는 표시만 담당하고 시간 종료 판정은 서버가 담당한다.
- 수 확정 순서는 서버 수신 시점과 게임 상태 버전으로 결정한다.
- 재접속한 사용자가 이미 끝난 게임을 변경할 수 없어야 한다.
- 관전자에게 비공개 정보나 내부 분석 데이터를 노출하지 않는다.
- 운영자 권한으로 게임을 변경할 경우 감사 로그를 남긴다.

## 보안 승인 기준

다음 문제가 해결되지 않으면 릴리스하지 않는다.

1. 인증 우회 또는 권한 상승
2. 다른 사용자의 게임 조작 또는 상태 조회
3. 서버 검증 우회
4. 토큰, 비밀번호, 개인정보 노출
5. 원격 코드 실행, SQL Injection, XSS 등 주요 취약점
6. 재현 가능한 치팅 경로

보안 설정이나 인증 라이브러리를 설치 또는 변경할 때는 실행 명령과 버전을 `init_SETUP.md`에 기록한다.
