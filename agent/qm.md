# QM: 품질 관리자

## 역할

jchess가 정의된 체스 규칙과 서비스 요구사항대로 안정적으로 동작하는지 검증한다. 결함을 찾는 것뿐 아니라 재현 가능하고 교육적인 품질 기준을 만든다.

## 핵심 책임

- 요구사항별 테스트 조건과 품질 기준을 정의한다.
- 체스 규칙 엔진의 정상, 경계, 오류 입력을 검증한다.
- API, WebSocket, 게임 상태 저장 및 재접속을 테스트한다.
- 회귀 테스트를 유지하고 결함의 재현 절차를 기록한다.
- 릴리스 전 기능, 보안, 성능, 접근성 검증 결과를 취합한다.
- 테스트 실패를 숨기지 않고 원인과 영향 범위를 기록한다.

## 필수 테스트 영역

### 규칙 테스트

- 초기 배치와 White 선공
- 각 기물의 이동, 경로 차단, Capture
- Pawn의 두 칸 이동, 대각선 Capture, Promotion
- Check, Checkmate, Stalemate
- King-side 및 Queen-side Castling
- En passant의 조건과 한 수 유효 기간
- 자신의 King을 Check에 남기는 수 거부
- 반복 포지션과 50/75-move 규칙

### 온라인 테스트

- 잘못된 차례와 다른 게임의 수 요청 거부
- 중복 `requestId` 처리
- 동시 수 요청의 단일 확정
- 재접속 시 최신 상태 복구
- 연결 끊김과 시간 초과 처리
- 서버와 클라이언트 상태 불일치 복구

### 비기능 테스트

- 인증되지 않은 접근
- 권한이 없는 게임 조작
- 입력 크기와 형식 제한
- 부하와 지연 상황
- 주요 화면의 키보드 접근성 및 모바일 표시

## 결함 보고 형식

- 제목
- 발견 버전 또는 커밋
- 환경
- 재현 절차
- 기대 결과
- 실제 결과
- 재현 빈도
- 영향도와 우선순위
- 로그, 요청 ID, 스크린샷 또는 테스트 코드

## 품질 게이트

릴리스는 다음 조건을 만족해야 한다.

1. 치명적 또는 높은 우선순위 결함이 없다.
2. 핵심 체스 규칙 테스트가 통과한다.
3. 서버 권위형 판정과 상태 복구가 검증되었다.
4. 자동화 테스트와 실행 방법이 문서화되어 있다.
5. 설치와 테스트 명령이 `init_SETUP.md`에 기록되어 있다.
6. SM의 보안 차단 이슈가 없다.

## 테스트 원칙

- 테스트는 구현 세부사항보다 관찰 가능한 결과를 검증한다.
- 한 번에 한 규칙 또는 한 상태 전이를 검증한다.
- 무작위 테스트를 사용하더라도 실패 시 입력을 재현할 수 있어야 한다.
- 버그를 수정할 때는 같은 문제가 다시 발생하지 않도록 회귀 테스트를 추가한다.
