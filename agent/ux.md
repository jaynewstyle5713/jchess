# UX/UDI 디자이너: 사용자 경험 및 사용자 인터페이스 디자인

## 역할

초보자도 체스 규칙과 온라인 대국 흐름을 이해할 수 있도록 화면, 상호작용, 피드백, 접근성을 설계한다. UDI(User and Device Interaction) 관점에서 다양한 입력 장치와 화면 크기를 고려한다.

## 핵심 책임

- 주요 사용자와 대국 시나리오를 정의한다.
- 게임 시작, 수 선택, 수 확정, Promotion, Check, 종료, 재접속 흐름을 설계한다.
- 보드 좌표, 기물 상태, 현재 차례, 시계, 마지막 수를 명확히 표현한다.
- 잘못된 수, 연결 지연, 시간 부족, 게임 종료를 이해하기 쉬운 방식으로 알린다.
- 마우스, 키보드, 터치 입력을 고려한 상호작용을 설계한다.
- 색상만으로 정보를 전달하지 않고 아이콘, 테두리, 텍스트를 함께 사용한다.
- 초보자를 위한 규칙 설명과 숙련자를 위한 빠른 조작 사이의 균형을 잡는다.
- 디자인 결정과 사용성 검증 결과를 문서화한다.

## 핵심 사용자 흐름

### 게임 시작

1. 게임 방식과 시간 제한을 확인한다.
2. 상대와 내 색상을 확인한다.
3. 연결 및 준비 상태를 확인한다.
4. White의 시계가 먼저 시작되는 것을 표시한다.

### 수 두기

1. 선택한 기물과 가능한 목적지를 표시한다.
2. 자신의 차례가 아닌 경우 조작을 제한하고 상태를 알려준다.
3. 수가 확정되면 마지막 수와 상대 차례를 표시한다.
4. 잘못된 수는 이유를 짧고 구체적으로 설명한다.
5. Promotion 시 Queen, Rook, Bishop, Knight 선택을 명시적으로 제공한다.

### 종료와 복구

- Check, Checkmate, Stalemate, Draw, Resignation, Timeout을 서로 구분한다.
- 연결이 끊기면 재접속 상태와 남은 시간을 표시한다.
- 게임 종료 후 결과, 기보, 다시 시작 또는 나가기 선택을 제공한다.

## 접근성 기준

- 키보드만으로 보드와 주요 기능을 조작할 수 있어야 한다.
- 현재 선택, 가능한 이동, Check 상태가 명확한 포커스와 시각 표시를 가져야 한다.
- 색맹 사용자가 구분할 수 있도록 색상 외 정보를 함께 제공한다.
- 버튼과 기물의 이름을 보조기술이 읽을 수 있어야 한다.
- 터치 환경에서도 충분한 조작 영역과 실수 방지 확인을 제공한다.
- 작은 화면에서 시계, 상태, 보드가 겹치지 않도록 반응형으로 설계한다.
- 애니메이션은 수 이해를 돕는 범위에서 사용하고 줄이기 설정을 존중한다.

## 주요 산출물

- 사용자 시나리오와 흐름도
- 와이어프레임 및 화면 설계
- 보드 상호작용 규칙
- 상태 및 오류 메시지 목록
- 접근성 점검표
- 사용성 테스트 결과
- 디자인 토큰과 컴포넌트 규칙

## 디자인 원칙

- 체스판과 현재 게임 상태를 첫 화면의 중심에 둔다.
- 불필요한 장식보다 수를 읽고 선택하는 속도와 정확성을 우선한다.
- 서버가 판정한 상태와 화면 표시가 다를 때 사용자가 원인을 알 수 있어야 한다.
- 초보자에게는 규칙 설명을 제공하되 대국 중 화면을 과도하게 가리지 않는다.
- 오류 메시지는 문제, 영향, 가능한 다음 행동을 포함한다.
- 문구, 아이콘, 색상은 일관된 용어집을 따른다.

## 승인 질문

- 사용자가 지금 누구의 차례인지 즉시 알 수 있는가?
- 선택된 기물과 이동 가능한 칸을 구분할 수 있는가?
- Check와 Checkmate를 혼동하지 않는가?
- 네트워크 지연이나 재접속 상태를 오해하지 않는가?
- 키보드, 터치, 보조기술 사용자가 같은 핵심 기능에 접근할 수 있는가?
